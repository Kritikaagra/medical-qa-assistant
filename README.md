# Fine-tuning a Medical Q&A Assistant with QLoRA

A from-scratch, end-to-end LLM fine-tuning project: **4-bit QLoRA
fine-tuning of Mistral-7B-Instruct-v0.2** on a domain-specific medical Q&A
dataset, sized to run on a single free-tier Colab T4 GPU, with a real
before/after evaluation rather than just a training-loss screenshot.

Built as a skills-demonstration project — see [`docs/theory.md`](docs/theory.md)
for the quantization/LoRA/QLoRA math this pipeline relies on.

> **Disclaimer:** this fine-tunes a small model on ~3,000 public Q&A pairs
> for one epoch. It is a demonstration of the fine-tuning *technique*, not
> a clinically validated medical tool. Do not use its outputs for real
> medical decisions.

## Why this project

Off-the-shelf LLMs answer general questions reasonably well but don't
consistently match the tone, scope, and phrasing you want for a specific
domain or audience. This project demonstrates the standard way teams close
that gap cheaply: **QLoRA** — quantize the frozen base model to 4-bit so it
fits in consumer/free-tier GPU memory, then train a small set of low-rank
adapter weights on top of it instead of the full model.

## What's actually in here

Unlike a single "run this tutorial notebook" demo, this repo is structured
like a small, reusable pipeline:

```
finetuning-medical-qa-assistant/
├── README.md                        <- you are here
├── requirements.txt
├── LICENSE
├── docs/
│   └── theory.md                    <- quantization / LoRA / QLoRA explainer
├── notebooks/
│   └── finetune_medical_qa.ipynb    <- Colab-ready, runs the full pipeline
├── src/
│   ├── config.py                    <- every hyperparameter, in one place
│   ├── prompting.py                 <- single source of truth for the prompt template
│   ├── prepare_dataset.py           <- download, clean, split, format the dataset
│   ├── finetune.py                  <- 4-bit load + LoRA + TRL SFTTrainer
│   ├── evaluate.py                  <- base vs. fine-tuned, ROUGE-L + qualitative report
│   └── inference.py                 <- CLI chat with the fine-tuned adapter
├── data/processed/                  <- generated by prepare_dataset.py (gitignored)
├── adapter/                         <- generated by finetune.py (gitignored)
└── results/
    └── eval_results.md              <- generated by evaluate.py
```

`prompting.py` matters more than it looks: the exact same prompt-building
function is used to construct training examples *and* inference prompts,
so there's no chance of the two silently drifting apart (a common source of
"fine-tuned model performs worse than base model" bugs).

## Model & dataset choices, and why

| Choice | Value | Why |
|---|---|---|
| Base model | [`mistralai/Mistral-7B-Instruct-v0.2`](https://huggingface.co/mistralai/Mistral-7B-Instruct-v0.2) | Ungated (no license click-through needed), well-documented instruct template, small enough to fit 4-bit on a T4, capable enough that fine-tuning improvements are visible. |
| Dataset | [`keivalya/MedQuad-MedicalQnADataset`](https://huggingface.co/datasets/keivalya/MedQuad-MedicalQnADataset) | Public, NIH-sourced medical Q&A pairs — a real domain-adaptation use case rather than a toy dataset. |
| Quantization | 4-bit NF4, double quantization | The QLoRA-paper default; shrinks the ~14GB base model to ~4-5GB so it fits a free-tier GPU. |
| LoRA rank | `r=16`, `alpha=32` | A common default that balances trainable-parameter count against adaptation capacity — see `docs/theory.md` for the tradeoff. |

**Note on the dataset schema:** `prepare_dataset.py` auto-detects the
question/answer column names from a candidate list (see `config.py`)
rather than hard-coding them, since dataset schemas on the Hub can change.
The script prints the detected columns and a formatted example on first
run — check that output before letting a full training run proceed.

## Setup & how to run

Designed for **Google Colab, T4 GPU runtime** (Runtime → Change runtime
type → T4 GPU). Everything also runs on any other CUDA GPU with ~16GB+
VRAM; adjust batch size in `src/config.py` if you have more or less.

1. Open [`notebooks/finetune_medical_qa.ipynb`](notebooks/finetune_medical_qa.ipynb)
   in Colab (or clone this repo and run the steps below locally).
2. `pip install -r requirements.txt`
3. Add a Hugging Face token as a Colab secret (`HF_TOKEN`) or `huggingface-cli login` locally — not required for this ungated model, but avoids rate limits.
4. Run the pipeline:

   ```bash
   python src/prepare_dataset.py   # no GPU needed
   python src/finetune.py          # GPU required, ~20-40 min on a T4
   python src/evaluate.py          # GPU required, writes results/eval_results.md
   python src/inference.py --question "What are the symptoms of anemia?"
   ```

All hyperparameters (dataset size, LoRA rank, batch size, learning rate,
etc.) live in [`src/config.py`](src/config.py) — change them there rather
than passing flags to each script.

## Results

`src/evaluate.py` runs the base model and the fine-tuned adapter on the
same held-out test questions (same underlying model in memory, adapter
toggled via PEFT's `disable_adapter()` — see the docstring in
`evaluate.py` for why that matters), scores both against the reference
answer with ROUGE-L, and writes a full report with qualitative examples to
[`results/eval_results.md`](results/eval_results.md).

That file is generated by an actual training run, so it isn't committed
with fake numbers here — run the pipeline above and it will be created
for you. Expect (and look for, when you run it) the fine-tuned model to:
- track the reference answers' phrasing/length more closely (higher
  average ROUGE-L than the base model), and
- consistently answer as a direct medical-information response rather than
  sometimes hedging, asking clarifying questions, or going off-topic.

## Known limitations

- **Small-scale by design.** 1 epoch over ~3,000 examples on a free GPU is
  enough to demonstrate the technique and see a measurable before/after
  shift, not to build a production-quality medical assistant.
- **ROUGE-L is a proxy metric.** It rewards phrasing overlap with a
  reference answer, not factual correctness. The qualitative examples in
  the eval report matter as much as the aggregate score.
- **Not medically validated.** See the disclaimer at the top of this file.
